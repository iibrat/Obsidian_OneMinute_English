- 【Bug 修复，已部署】右下角悬浮队列按钮（移出队列/下一篇）在右侧边栏收起/展开后位置不更新。
  - 根因：`updateQueueBar()` 只在 `active-leaf-change` / `file-open` / `layout-change` / `window resize` 这些**离散事件**触发时用 `view.containerEl.getBoundingClientRect()` 量一次位置。Obsidian 侧栏开合是**带动画的**，事件触发时面板还在过渡中，量到的是动画中途（或旧的）矩形，动画结束后没有新事件再纠正。
  - 修法：改用 `ResizeObserver` 盯住当前 MarkdownView 的 `containerEl`，容器每变一帧就 `requestAnimationFrame` 里重算一次位置，动画过程中平滑跟随，结束后自动落位。新增字段 `queueBarObserver` / `queueBarObserved` / `queueBarFrame`，新方法 `observeQueueBarContainer(el)`（同一元素不重复 observe，切换 leaf 时先 disconnect 再 observe），无素材视图时 disconnect，`onunload` 里 disconnect + cancelAnimationFrame。
  - 【架构说明，供以后参考】为什么不能只靠 CSS：`.ome-queue-bar` 是 `position: fixed` 且挂在 `document.body` 上，fixed 的包含块是**视口**（整个 Obsidian 窗口），写 `right: 50px` 只表示"离窗口右边缘 50px"，侧栏开合时笔记面板右边缘在动、窗口右边缘不动，所以按钮不动。若要走纯 CSS 路线，必须把按钮挂进笔记面板自己的容器（`.workspace-leaf-content`，它 `position: relative` 且**不滚动**，滚动的是里面的 `.view-content`），用 `position: absolute; right: 24px; bottom: 46px` 才会自动跟随；代价是要往 Obsidian 内部 DOM 注入节点、leaf 切换/销毁时要自己搬运，且依赖 Obsidian 的内部结构不变。当前选的是 ResizeObserver（挂在 body 上更稳，不碰内部 DOM）。
  - 用户当时质疑"是不是应该用 right:50px 这种 CSS"，已在回复中解释上面两种路线的差别并给出可切换的选项。
