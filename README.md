# One Minute English

一个用于集中管理英语素材和话题进度的 Obsidian 仪表盘插件。

我一直想把英语学好，网上看了各种学英语的方法但感觉都不管用，其实根本问题还是对学习的理解有误，一直在学习方法、技巧之类的，很少有花时间真正去练习英语。

当我意识到这一点，我开始尝试着每天用英语写点什么，然后录成视频说出来。但新的问题又出现了，我好像没有什么话说，半天憋不出3句话来。

最近我想到一个办法，也许能解决没话说的问题，我做了这个 obsidian 插件，配合 Claudian 插件。平时先收集各种感兴趣的素材，然后用AI从素材中提取各种话题，并且指导我针对这个话题写一段一分钟的英语内容。平时收集自己感兴趣的素材，然后用 AI 从素材中提取话题，并且引导我写一段一分钟的英语口语表达内容。

这个插件其实跟整个学过过程没有关系，只是一种我个人比较喜欢的展示方式，整体页面设计是抄另一个插件的。https://github.com/kuzzh/obsidian-startpage

本插件的“AI”设置页可以保存供应商、模型和提示词，并测试连接；高亮卡片支持选择提示词直接生成内容。自动创建话题文件和双链等工作流仍可配合 Claudian 使用。
还需要一段 AI 提示词，用来从素材中提取话题，我有一个自己用的，放在“AI角色” 目录，大概逻辑是“从素材中提取话题，把每个话题生成一个md文档，放在指定的目录中，并且对话题和素材进行双向链接。”



## 使用

1. 安装依赖并构建：`npm install`、`npm run build`。
2. 将 `manifest.json`、`main.js`、`styles.css` 复制到库内 `.obsidian/plugins/one-minute-english/`。
3. 在 Obsidian 的“第三方插件”中启用 **One Minute English**。
4. 打开插件设置，选择素材目录、话题目录，并配置话题状态属性。
5. 点击左侧边栏的语言图标，或在命令面板执行“打开主页”。
6. 首页统计区的第四张卡片为“影子跟读工具”，点击可查看二维码，使用微信扫码打开小程序。二维码内嵌于插件代码，无需联网加载图片或另行复制附件。

## AI 配置

打开插件设置中的 **AI** 标签页，供应商配置自动保存，提示词在编辑窗口中点击“保存”后生效：

1. 使用预填的 DeepSeek 配置，或点击“添加供应商”保存其他供应商或模型配置；在“当前供应商”中切换。
2. 填写完整 API 地址（默认 `https://api.deepseek.com/chat/completions`）、API Key 和模型名称。默认模型为 `deepseek-v4-flash`，也可以填写供应商提供的其他模型 ID。
3. 配置“思考参数格式”“开启思考”和“思考深度”。DeepSeek 格式使用 `thinking.type` 控制开关，开启时发送 `reasoning_effort`；兼容接口格式使用 `reasoning_effort`，关闭时发送 `none`；不支持这些参数的接口可选择“不发送思考参数”。具体取值以模型文档为准。
4. 点击“测试连接”验证当前模型和思考配置。测试只发送一句简短消息，不发送笔记或自定义提示词，会产生少量调用用量。
5. 提示词以列表显示名称、内容摘要和默认标记。点击“添加提示词”或“编辑”打开独立窗口，填写名称和多行内容后点击“保存”；取消或关闭不会修改已有内容。支持复制、删除及设置默认提示词。高亮卡片右下角的 AI 图标可选择任意一条提示词提交生成。
6. 首次升级会自动加入“口语生成”提示词：以高亮和补充内容为中心，参考原文，生成 B1 难度的美式英语口语正文，目标约 90–110 词、40–60 秒（实际时长取决于语速）。可以自由编辑或删除，后续重启不会覆盖修改或恢复删除项。

DeepSeek 的思考开关及深度规则参见[官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)：支持 `low`、`high`、`max`，`medium` 和 `xhigh` 会映射为 `high`。

AI 配置和 API Key 保存在插件的 `data.json` 中，密钥在输入框中隐藏显示，但在文件中为明文；同步或分享该文件前请检查其中的密钥。

## 高亮与补充内容

1. 在 Markdown 编辑器中选中一段文字，点击选区上方出现的“加入高亮”（也可以从命令面板执行“将选中内容加入高亮”）。
2. 插件会在原笔记中写入带唯一标识的 `<mark>` 高亮，并自动打开右侧高亮栏。
3. 每条高亮下方都可以添加或编辑“补充内容”；移开输入框后会自动保存，`Ctrl/Cmd + Enter` 也可以保存。
4. 点击卡片中的来源路径可以重新打开原笔记。
5. 点击高亮卡片右下角的“转为笔记”图标，可以为笔记命名并将高亮内容保存到设置中的“话题目录”；新笔记会自动添加一个空列表状态属性（优先使用设置中的“状态属性”，否则使用“状态”），转换完成后，原笔记与新笔记底部会自动添加彼此的双链。
6. 点击卡片右下角的删除图标并确认，可删除卡片及补充内容，同时保留原文并取消其高亮样式。
7. 右侧高亮栏默认只显示当前笔记的高亮；当前笔记没有高亮时不显示卡片。
8. 点击右侧高亮栏顶部的“高亮总览”图标，会在中央打开双栏页面：左侧选择包含高亮的笔记，右侧查看对应的高亮卡片。
9. 点击卡片右下角的 AI 星光图标，从设置中的提示词列表选择一条，即向当前供应商发送完整笔记原文、当前高亮和补充内容，使用当前模型及思考设置。正在编辑的原文和刚输入的补充内容也会包含在内。
10. AI 调用前须在“设置 → 常规”中配置有效的“话题目录”。AI 会在一次回复中返回简体中文标题和正文，标题固定为中文、正文语言遵循所选提示词，用标题直接创建独立 Markdown 笔记，不再按原笔记名称拼接。内容依次包含生成正文、本次提交时的“高亮内容”“补充内容”和指向原笔记的“来源笔记”链接（补充为空时显示“未填写”），并初始化话题状态属性；高亮卡片中显示可点击的新笔记链接。保存前不扫描目录或预查同名文件，只有创建失败且确认该路径已存在时，才在标题后加时间戳重试；时间戳仍重名时再加序号。卡片链接在 Obsidian 内重命名笔记或文件夹时同步更新。
11. 关闭进度弹窗后仍会继续生成，同一张卡片生成期间不会重复提交。写入失败时保留弹窗中的正文供复制。旧版保存在卡片中的内容可从 AI 菜单的“历史结果”查看，不会自动改写或迁移。
12. 在 Obsidian 内删除生成笔记或其所在目录时，相关卡片链接会自动移除并保存；若笔记在插件未运行时或库外被删除，点击失效链接也会自动清理。高亮文字、补充内容和其他笔记链接会保留。
13. AI 请求期间，对应卡片右下角显示旋转的加载图标；成功、失败或超时后恢复 AI 图标。关闭进度窗口不影响加载状态，点击图标仍可查看进度。

高亮卡片数据保存在插件的 `data.json` 中，会跟随知识库内的 `.obsidian/plugins/one-minute-english/` 一起同步；文件或文件夹在 Obsidian 内重命名时，来源路径也会自动更新。

## 发布新版本

项目已配置 GitHub Actions。推送与 `manifest.json` 版本号相同的 Git 标签后，会自动构建插件、创建 GitHub Release，并上传 `main.js`、`manifest.json`、`styles.css` 和安装 ZIP。

例如发布 `1.0.1`：

```powershell
npm run version:set -- 1.0.1
npm run build
git add manifest.json versions.json package.json main.js
git commit -m "Release 1.0.1"
git push origin main
git tag 1.0.1
git push origin 1.0.1
```

标签必须使用 `1.0.1` 这种格式，不要添加 `v`，并且必须与 `manifest.json` 中的 `version` 完全一致。发布进度可在仓库的 **Actions** 页面查看，完成后版本会显示在仓库右侧的 **Releases** 区域。
